# PRD: 오늘 뭐 먹지? (팀 점심 룰렛)

## 1. 컨셉
팀원들이 함께 식당을 모으고, 조건(음식 종류, 최근 방문, 날씨, 거리)에 맞춰 룰렛을 돌려 오늘 점심을 정하는 팀용 웹앱.

## 2. 해결할 문제
- 식사 장소를 정하는 데 매번 시간이 걸린다.
- 식당 정보가 여러 곳에 흩어져 있다.
- 익숙한 식당만 반복해서 가게 된다.

## 3. 사용자와 환경
- 대상: 5~20명 규모의 팀. 동시 접속은 소수.
- 환경: 모바일/PC 반응형 (점심 직전 폰 사용 고려).
- 인증: 아이디/비밀번호 로그인(회원가입 팝업). 가입은 누구나 가능하다(초대 코드 없음). 아이디가 곧 표시 이름이며, 추가/별점/방문/제외 시 작성자는 서버가 로그인 사용자로 정한다. 로그인 상태는 토큰(브라우저 localStorage, 30일)으로 유지하고, 비밀번호는 해시로만 저장한다.

## 4. 기능 요구사항

### 4.1 식당 관리
| 항목 | 구분 | 비고 |
|---|---|---|
| 이름 | 필수 | |
| 카테고리 | 필수 | 고정 목록: 한식, 중식, 일식, 양식, 분식, 기타 |
| 가격대 | 필수 | 구간: ~1만원, 1~1.5만원, 1.5만원~ |
| 도보 시간(분) | 필수 | 숫자 입력 |
| 태그 | 선택 | 복수 선택: 차가운 음식, 국물 요리 (날씨 가중치용) |
| 대표 메뉴 | 선택 | 텍스트 1개 |
| 위치 | 선택 | 주소/설명 텍스트 |
| 메모 | 선택 | |
| 추천자 | 자동 | 등록한 로그인 아이디 |

- 등록, 수정, 삭제, 목록 조회
- 목록에서 식당 이름을 누르면 상세 정보 표시 (평균 별점, 한줄평, 최근 방문일 포함)

### 4.2 룰렛
- 필터
  - 카테고리 (복수 선택 가능)
  - 도보 시간: 5분 / 10분 / 15분 이내 등 선택
  - 최근 방문 제외 기간: 끔 / 3일 / 7일(기본) / 14일
  - 날씨: 선택 안 함 / 더움 / 추움 / 비
- 후보 선정
  1. 필터 조건과 오늘 제외 목록을 반영해 후보를 추린다.
  2. 후보가 8개를 초과하면 가중 무작위로 **최대 8개**를 뽑아 룰렛에 올린다. 8개 이하면 전부 올린다.
  3. 날씨 가중치: 더움 → "차가운 음식" 태그, 추움/비 → "국물 요리" 태그 해당 식당의 뽑힐 확률 2배.
- 룰렛 조각 크기는 모두 동일하다 (가중치는 후보 선정 단계에만 적용).
- 결과 후 "여기로 확정"(방문 기록 저장) 또는 "다시 돌리기" 선택.
- 후보가 0개면 안내 메시지를 표시한다.

### 4.3 방문 기록
- 룰렛 결과 확정 시 식당, 로그인 아이디, 날짜를 저장한다.
- 같이 간 사람, 방문 메모는 이번 범위에 포함하지 않는다.
- 최근 방문일은 "최근 안 간 곳" 필터와 상세 화면에 사용한다.

### 4.4 별점/한줄평
- 1인 1식당 1개 별점(1~5). 다시 입력하면 덮어쓴다.
- 한줄평은 선택 입력.
- 식당 상세에 평균 별점과 한줄평 목록을 표시한다.

### 4.5 오늘 제외
- 팀원 누구나 식당을 "오늘 제외"로 지정할 수 있다. 팀 전체에 적용된다.
- 제외한 사람의 아이디를 표시하고 해제도 가능하다.
- 당일(날짜 기준)에만 유효하며 다음 날 자동으로 풀린다.

## 5. 비기능 요구사항
- 3티어 물리 분리: 프론트엔드(React), 백엔드(FastAPI), DB(MariaDB)를 각각 별도 서버(호스트)에서 실행한다. 기존에는 WSL 한 곳에서 모두 실행했다.
  - 프론트엔드 서버: React 빌드 결과물 서빙. 사용자가 접속하는 유일한 진입점이며 외부(ngrok 등)에는 이 서버만 공개한다.
  - 백엔드 서버: FastAPI. 프론트엔드 서버가 `/api` 요청을 이곳으로 전달한다. 외부에 직접 공개하지 않는다.
  - DB 서버: MariaDB. 백엔드 서버에서만 접속할 수 있고 외부에 공개하지 않는다.
- 통신 방향은 사용자 → 프론트엔드 → 백엔드 → DB 한 방향만 허용한다. 프론트엔드가 DB에 직접 접속하지 않는다.
- DB 접근은 백엔드에서만 하며, DB 접속 정보는 프론트에 포함하지 않는다.
- 서버 주소, 포트, 접속 정보는 코드에 쓰지 않고 환경변수로 분리한다. (백엔드: DB_HOST 등, CORS_ORIGINS / 프론트엔드: 백엔드 주소)
- DB 계정은 백엔드 서버 주소에서의 접속만 허용하고, 방화벽도 백엔드 서버에만 DB 포트(3306)를 연다.

## 6. 범위 밖 (이번에 만들지 않음)
소셜 로그인, 비밀번호 찾기, 지도 API 연동, 자동 날씨 연동, 결과 공유/투표, 사진 업로드.

## 7. 확장 후보
- 방문 시 동행자/메모
- 룰렛 조각 크기에 가중치 반영
- 자동 날씨 연동
- 초대 코드 등 가입 제한, 비밀번호 변경
